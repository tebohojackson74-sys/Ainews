# Security Policy

## Reporting a vulnerability

Do not disclose security vulnerabilities in public issues.

Until a dedicated security contact is configured, report suspected vulnerabilities privately to the repository owner through GitHub and include:

- affected file or component;
- reproduction steps;
- security impact;
- relevant logs or screenshots with secrets removed.

Never include passwords, API keys, tokens, private source information or personal data in a report.

## Scope

Security reports may include:

- authentication and authorization flaws;
- accidental exposure of credentials or personal data;
- unsafe AI/data handling;
- dependency vulnerabilities;
- CMS publication bypasses;
- access-control failures;
- malicious file or media upload paths.

## Response target

The project should acknowledge a credible report within 3 business days and establish a remediation plan based on severity.

## Disclosure

Do not publicly disclose an unresolved vulnerability until the project has assessed the risk and coordinated a safe disclosure timeline.
